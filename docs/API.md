# Backend API веб-прототипа

HTTP API для чата, истории, заявок и передачи вопроса специалисту. Использует тот же Consultant Engine, что и конкурсный `solution.py`. Интерактивная документация доступна на `/docs` после запуска.

## Запуск

Backend требует Python 3.11 или новее. Конкурсный `solution.py` по-прежнему работает на стандартной библиотеке и от backend не зависит.

Терминал 1, backend из корня репозитория

```bash
python3.11 -m venv .venv && source .venv/bin/activate
```

```bash
pip install -r backend/requirements.txt
```

```bash
DATA_DIR=local-data ADMIN_TOKEN=придумайте-токен LLM_BASE_URL=... LLM_API_KEY=... LLM_MODEL=... uvicorn backend.app:app --port 8000
```

Терминал 2, React-клиент на Vite. Vite проксирует `/api` на `http://localhost:8000`, интерфейс открывается на `http://localhost:5173`.

```bash
cd react-frontend/client && npm install && npm run dev
```

Команды backend выполняются из корня репозитория. В `DATA_DIR` должен лежать `knowledge-base.zip`. Без переменных LLM сервер стартует, но чат отвечает 503, а `/api/health` показывает `"engine": "not_configured"`.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `DATABASE_PATH` | `local-data/web.sqlite3` | Файл SQLite с сессиями и заявками |
| `CORS_ORIGINS` | `http://localhost:5173` | Адреса фронтенда через запятую |
| `ADMIN_TOKEN` | пусто | Токен для списков сессий, заявок и передач в заголовке `X-Admin-Token`. Если не задан, эти списки закрыты (403) |
| `SESSION_RETENTION_DAYS` | 30 | Через сколько дней без активности сессия удаляется, 0 отключает |
| `LEAD_RETENTION_DAYS` | 90 | Срок хранения заявок и передач специалисту, 0 отключает |

Остальные переменные движка описаны в [ENGINE.md](ENGINE.md).

## Сценарий для фронтенда

1. При открытии чата или по кнопке «Новый диалог» вызвать `POST /api/sessions` и запомнить `id`. Новая сессия не видит историю других.
2. Каждое сообщение отправлять в `POST /api/sessions/{id}/messages`. В ответе реплика консультанта, источники и время ответа для режима отладки.
3. Если в ответе `lead_suggested: true` или клиент нажал «Оставить заявку», вызвать `POST /api/sessions/{id}/lead/draft`. Вернётся черновик с найденными в диалоге полями, резюме и списком недостающих полей. Модель здесь не вызывается, потому что согласия ещё нет.
4. Показать черновик клиенту, дать поправить поля и поставить галочку согласия на обработку данных. ФИО, телефон и компания обязательны.
5. Отправить `POST /api/sessions/{id}/lead`. При ошибках вернётся 422 с текстом и полями, которые нужно исправить.
6. Если консультант не может ответить, кнопка «Передать специалисту» вызывает `POST /api/sessions/{id}/handoff`.

Для истории диалогов клиент хранит `id` своих сессий в `localStorage`. Список с заголовками отдаёт `POST /api/sessions/lookup`, сам диалог `GET /api/sessions/{id}`. Общий список `GET /api/sessions` административный и без токена закрыт.

## Эндпоинты

### `GET /api/health`
```json
{"status": "ok", "engine": "ready"}
```

### `POST /api/sessions` → 201
```json
{"id": "6f1c...", "created_at": "2026-11-13T10:00:00+00:00", "updated_at": "2026-11-13T10:00:00+00:00"}
```

### `POST /api/sessions/lookup`
Тело `{"ids": ["6f1c...", "a2b4..."]}`, не больше 50 штук. Возвращает только найденные сессии из переданных, новые сверху. Токен не нужен, потому что без `id` сессию не найти.
```json
[{"id": "6f1c...", "created_at": "...", "updated_at": "...", "title": "Хотим солнечную станцию", "message_count": 4, "has_lead": false}]
```

### `GET /api/sessions/{id}`
Сессия и все сообщения. 404, если сессии нет.
```json
{
  "id": "6f1c...",
  "created_at": "...",
  "updated_at": "...",
  "messages": [
    {"id": 1, "role": "user", "content": "Хотим солнечную станцию", "sources": [], "elapsed_ms": null, "created_at": "..."},
    {"id": 2, "role": "assistant", "content": "Да, ...", "sources": ["20-products/23-solar.md > Размещение"], "elapsed_ms": 2350, "created_at": "..."}
  ]
}
```

### `DELETE /api/sessions/{id}` → 204
Удаляет сессию и её сообщения. Заявки остаются, у них обнуляется `session_id`.

### `POST /api/sessions/{id}/messages`
Тело `{"text": "вопрос"}`, от 1 до 4000 символов.
```json
{
  "user_message": {"id": 3, "role": "user", "content": "...", "sources": [], "elapsed_ms": null, "created_at": "..."},
  "assistant_message": {"id": 4, "role": "assistant", "content": "...", "sources": ["..."], "elapsed_ms": 2100, "created_at": "..."},
  "lead_suggested": false
}
```
`sources` и `elapsed_ms` нужны для режима отладки. 503, если модель не настроена.

### `POST /api/sessions/{id}/lead/draft`
Тело может содержать уже введённые поля `{"full_name": "...", "phone": "...", "company": "..."}`, они важнее найденных в диалоге. Черновик собирается без модели. Телефон ищется в репликах клиента, резюме собирается из его реплик, а телефоны, почта и ФИО в нём маскируются.
```json
{
  "full_name": "",
  "phone": "+79001234567",
  "company": "Ромашка",
  "summary": "Клиенту нужна солнечная станция на складе...",
  "errors": {},
  "missing": ["full_name"],
  "is_complete": false,
  "message": "Чтобы передать заявку менеджеру, напишите, пожалуйста, ФИО."
}
```

### `POST /api/sessions/{id}/lead` → 201
Тело `{"full_name": "...", "phone": "...", "company": "...", "summary": "...", "consent": true}`. Если `summary` пустое, резюме по диалогу пишет модель, это происходит только после согласия. Контакты в резюме маскируются, и в присланном клиентом тоже. Без `consent: true` или при ошибках в полях ответ 422.
```json
{"id": "a2b4...", "session_id": "6f1c...", "full_name": "Тестов Тест", "phone": "+79001234567", "company": "ООО Ромашка", "summary": "...", "created_at": "..."}
```
Ошибка валидации
```json
{"detail": {"message": "Укажите телефон в формате +7 900 000-00-00.", "draft": {"errors": {"phone": "..."}, "missing": ["phone"]}}}
```
После сохранения в историю сессии добавляется сообщение консультанта о том, что заявка передана.

### `POST /api/sessions/{id}/handoff` → 201
Тело `{"question": "..."}` или `{}`, тогда берётся последний вопрос клиента. В историю добавляется сообщение консультанта о передаче.
```json
{"id": "...", "session_id": "...", "question": "...", "created_at": "...", "assistant_message": {"id": 7, "role": "assistant", "content": "Передали ваш вопрос специалисту...", "sources": [], "elapsed_ms": null, "created_at": "..."}}
```

### Списки для менеджера
`GET /api/sessions`, `GET /api/leads`, `GET /api/handoffs`, параметр `limit` до 500. Нужен заголовок `X-Admin-Token` со значением `ADMIN_TOKEN`. Без заданного `ADMIN_TOKEN` ответ 403, с неверным токеном 401. В списке сессий есть `title` (первый вопрос), `message_count` и `has_lead`, туда попадают и диалоги без заявки.

## Данные и безопасность

- Сессия адресуется случайным UUID, без него чужую историю не получить.
- Тексты сообщений и контакты не пишутся в логи.
- Заявка сохраняется только с согласием клиента. До согласия история диалога в модель для заявки не отправляется.
- Административные списки закрыты, пока не задан `ADMIN_TOKEN`.
- Веб-консультант просит контакты, когда клиент сам хочет оставить заявку. Конкурсный запуск этого правила не содержит.
- Устаревшие сессии и заявки удаляются при старте сервера по срокам из переменных.
- База лежит в `local-data/`, папка в `.gitignore`. В разработке используются только выдуманные данные.
