# Политика безопасности

Эти правила действуют для публичного репозитория MTS EnergyTool AI Consultant и локальных копий.

## Что запрещено публиковать

- API-ключи, токены, пароли, приватные ключи и иные секреты.
- Исходную закрытую базу знаний МТС, копии, выгрузки, производные материалы и индексы, содержащие её содержимое.
- Закрытые тесты организаторов, ответы, материалы проверки и иные данные, публикация которых не разрешена.
- Реальные персональные данные и реальные пользовательские диалоги.

Для разработки берите только тестовые или выдуманные персональные данные. Реальные диалоги в Git хранить нельзя.

## Работа с конфигурацией и секретами

- `.env` и локальные конфигурации с секретами не добавляются в Git. Используйте `.env.example` только с безопасными именами параметров и пустыми/примерными значениями, без действующих ключей и паролей.
- Не вставляйте секреты в исходники, документацию, Issues, Pull Request, скриншоты и логи.
- Перед коммитом проверьте `git status` и `git diff --cached`. Убедитесь, что в staged-файлах нет секретов и закрытых материалов, а `.gitignore` исключает локальные данные.

## Сообщение об уязвимостях

Если в GitHub для репозитория доступен приватный канал **Security Advisories**, сообщите об уязвимости через него, а не в публичной Issue. Если канал недоступен, сообщите владельцу репозитория способом, который команда использует для приватной связи. Не раскрывайте детали публично до подготовки исправления.

## Если секрет случайно опубликован

1. Немедленно отзовите или ротируйте секрет у соответствующего владельца сервиса; удаление файла из последующего коммита не делает раскрытый секрет безопасным.
2. Ограничьте доступ к затронутому сервису и проверьте журналы использования секрета.
3. Удалите секрет из репозитория и связанных артефактов; при необходимости согласуйте очистку истории с владельцем репозитория.
4. Уведомите владельца репозитория приватно и проверьте, что исправленная версия не содержит секрета.
